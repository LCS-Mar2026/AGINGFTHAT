# AFT client workspace — review version 1

This is a draft application for review. It does not replace the current live website. Source code belongs on a review branch, outside the current Pages deployment whitelist.

## What is implemented

- Shared AFT dashboard design for Elite A, Virtual B, Intensive C and Level 1.
- Administrator access to every client, assessment and source file.
- Open New Client: enter first and last name, programme and start date. A named client record and its assessment folders are created without a login.
- One fact find per client, using blank field definitions from Tony's current execution copy; no Tony-specific data is included in this project.
- Editing and saving the fact find creates a dated downloadable raw HTML snapshot named First_Last_Fact_Find.html. Earlier snapshots are retained.
- On-demand issuance of a unique client username and temporary password. Clients change the temporary password before accessing their files.
- Client view contains only that client's original raw files. No dashboard measurements or computed scores are returned by the client API.
- Practitioner report uploads assigned to client, assessment and category. Administrator enters measurements from reports; OCR/extraction is not implemented.
- Bio-age charts plot dated recorded values; no future assessment results are filled in.
- Password hashing, server-side sessions, CSRF tokens, origin checks, login rate limiting and ownership checks on every file download.
- Persistent SQLite records and raw files outside the public directory; data must not be committed to GitHub.

## Review without running a backend

Open public/index.html in a browser and click Explore the V1 review preview. It uses fictional records. Select Open New Client, complete the blank fact find, save it, upload a sample file and switch to View as client. Preview changes exist in memory for this session only. The preview does not create real user accounts.

## Run the backend locally

Requires Node 24 or later; no npm dependencies are needed. Run npm test for the isolation and onboarding integration tests.

Set AFT_ADMIN_PASSWORD securely in your environment before the first start (at least 14 characters). AFT_ADMIN_USERNAME defaults to lee. No default password is supplied or stored in source code. Run npm start. HOST defaults to 127.0.0.1 and PORT to 8787.

For local HTTP development only, set AFT_COOKIE_SECURE=false. Production requires HTTPS and the default Secure cookie setting. Set AFT_ORIGIN to the exact HTTPS portal origin. Set AFT_DATA_DIR to persistent private storage, outside the public website directory. No real client data should be entered before production hosting, backups, data-protection review and access testing are completed.

GitHub Pages cannot run this backend. A production host and persistence/backup arrangements must be selected before launch. This draft uses SQLite and a private filesystem; migration to an approved managed database/object store remains possible.

## Current programme assumptions

Elite A and Virtual B: baseline, Month 6 midpoint, Month 12 endpoint. Intensive C: baseline and Month 3 endpoint. Level 1: one assessment. Programme membership is saved on the client record rather than inferred from a viewer toggle. Upgrades and assessment rescheduling need a defined policy.

## Model status

Level 1 weights are approved: systolic BP 20%, diastolic BP 10%, resting HR 10%, sitting-rising 30%, body fat 15%, muscle estimate 10%, visceral index 5%. Posture and RENPHO metabolic age are excluded from the score.

Age-reference calibration remains under review. Level 1 age entry/calculation is disabled. Elite age results are recorded from an externally reviewed model, not generated by this draft. Fictional preview results are clearly marked sample records.

## Refinement decisions

1. Verify Month 6 as midpoint for Elite and Virtual; earlier discussions also mentioned Month 4/8 programme reviews. Programme reviews and measured checkpoints can be separate.
2. Confirm whether clients should see all raw files or only practitioner reports. Currently every saved raw file, including the fact find, is visible once login access is issued.
3. Approve the fact-find permissions, programme agreement and signature workflow. Fields are retained, but legal wording and enforceable digital execution are not implemented here.
4. Confirm PDF alongside editable HTML for fact-find snapshots.
5. Decide whether extracted report readings require administrator approval before updating charts. Recommended: require approval.
6. Confirm final production hosting, admin two-factor authentication, password recovery, backup/retention and practitioner access. Two-factor authentication and recovery are not implemented in this draft.
7. Decide how to handle Level 1 conversions to paying programmes while retaining the original assessment and files.

## Validation

The integration test covers admin onboarding without login issuance, delayed client access, mandatory initial password change, cross-client file denial, admin access to both clients, exclusion of measurements from client responses, fact-find escaping, CSRF checks, persistent assessment data and no public raw-data directory route. Browser rendering and a production security review are still required before launch.
